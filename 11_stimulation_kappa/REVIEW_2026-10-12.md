## Issues

### 1. CRITICAL: the real-data fits used bins 0–699, not the preregistered 300–559
- **Where:** `run_stimfit.py:24` (`T_LO, T_HI = 0, 700`) and `run_stimfit.py:79-82` (`crop` → `bspline_basis_crop(0, 700)`).
- **What's wrong:** PREREGISTRATION §3 and validation amendment 3 fix the fitted range at 300–559, with a basis built on those bins. The real-data runner never set this range. It fits all 700 bins with `bspline_basis_crop(0, 700)`. Because `fine=(340, 560)` is hard-coded, the knots are every 25 bins from 0 to 325, every 5 bins from 340 to 555, and then **one knot interval from 555 to 699, which is 144 bins covered by a single cubic piece** (`tvfield_model_basis.py:21`). So the late-reach and post-reach fields cannot follow the PSTH. For example, a rate step at bin 600 leaves an RMS residual of 0.21 over 560–699.
- **Evidence that the fits really used 700 bins:** in `fits_all.csv`, the primary log-likelihood divided by (non-excluded reaches × N × 700) is 0.41–0.66 nats per neuron-bin. That is below ln 2 = 0.69, as it must be. Divided by 260 bins instead, it would be 1.1–1.8 nats, which is impossible for binary data with fitted fields. All 21 sessions agree.
- **Consequence:**
  - J is shared and is now dominated by bins far from the reach (0–300 and 560–699), including the badly fitted 555–699 stretch. PSTH structure that the fields miss is absorbed as spurious covariance into J.
  - Each window's κ then measures how reach-phase coupling differs from that off-reach J. This plausibly explains why real per-window κ is large in *both* windows: κ_control ranges from −0.80 to +0.96 (median over subsets), even though no stimulus is present. Synthetic validation gave |κ_control| ≤ 0.03.
  - It also explains the strong dependence on λ_B in RESULTS R9 and Caveat 2. With 2.7× more bins, the 6-bin window's share of the per-bin-normalised likelihood shrinks, so λ_D is effectively 2.7× stronger relative to the window information. That is the mechanism of validation run 1's false positive.
  - None of the validation runs tested this configuration.
  - RESULTS.md Caveat 7 says "Fits use bins 300–559 only", which is false. The deviation is undisclosed.
  - S1, all S1 sensitivity analyses, S2 and S3 all come from this model.
- **Failure scenario:** a session whose post-reach rate rebound (bins 560–700) is not captured gets an inflated J. The κ in each window then shrinks or inflates by phase, and Dκ inherits a phase-dependent term that is unrelated to stimulation. The pulse-vs-control phase difference (pulse onsets vs pseudo-onsets, fixed 401–406) would produce the same effect, which matches R3: the result depends on the control window.
- **Severity:** critical. The reported S1 and S2 are not the preregistered analysis. The direction of the effect on HL −0.24 is unknown, so a refit at 300–559 is required.
- **Confidence:** high.

### 2. MAJOR: the shuffle null misaligns each neuron's stimulus response with its pulse window
- **Where:** `run_stimfit.py:91-96` (`shuffle_blocks`) and `run_stimfit.py:110-116` (design built before shuffling; the masks stay with the rows).
- **What's wrong (answer to check 1):** `make_design` builds the pulse mask from row r's own onset o_r. `shuffle_blocks` then replaces neuron i's data in row r with reach π_i(r). Neuron i's onset-locked response therefore sits at o_{π_i(r)} while its window is at o_r. On the real onsets, P(o_{π(r)} ≠ o_r) is 0.53–0.90 per session. The mean |Δonset| is 0.7–5.6 bins and the maximum is 3–20 bins, against a 6-bin window.
- **Consequence for null-corrected Dκ:**
  - In the null, the pulse-locked rate change is smeared across the window edges.
  - The leftover rate heterogeneity is independent across neurons, so it creates no pairwise covariance.
  - Shuffling also destroys cross-neuron covariance, so the fitted J is about 0 and κ is weakly identified.
  - So mean_null κ_pulse does **not** reproduce the aligned, shared-across-neurons rate change that causes the rate-only bias. That bias (+0.08 in validation scenario B) is the stated reason for the correction in PREREG §5.
  - Instead the null estimates a "no coupling, smeared response" κ. Its means are about 0 in most sessions (range −0.35 to +0.23), with SD up to 0.76. The correction therefore mostly adds noise and removes nothing specific. This fits the observation that corrected and raw S1 agree (−0.236 vs −0.233).
  - The null is not the intended one. It does keep each neuron's response, but not locked to the window. It is also a null with J ≈ 0, whereas the bias it should estimate occurs at the real J.
- **Fix:** permute only within groups of reaches that share floor(onset), or shift each reach to onset-relative time before permuting.
- **Severity:** major. It does not change the S1 conclusion, since the raw value is also inconclusive, but "null-corrected" should not be read as "rate-confound corrected". The correction was also never validated (PREREG §9).
- **Confidence:** high on the mechanism; medium on the size of the bias it fails to remove.

### 3. MAJOR: laser onsets are stored at 10-ms precision, and a floating-point floor puts 38% of pulse windows one bin early
- **Where:** `extract_laser_onsets.py:21` (`"%.6g" % x` for stimtime), `merge_laser_onsets.py:22` (`(st - t0) / dt`) and `run_stimfit.py:57` (`np.floor`).
- **What's wrong:**
  - **Precision lost at extraction.** `%.6g` keeps 6 significant digits of an absolute time in seconds. For stimtime ≥ 1000 s, the resolution is 0.01 s, which is one full bin. That covers 325 of the 354 primary stim_1 reaches. As a result, 327 of 354 onsets come out integer-valued (only 27 of the 29 reaches with stimtime < 1000 s have a fractional part). The "bin containing the laser time" (PREREG §4) can no longer be determined: the true time lies within ±5 ms of the stored value.
  - **Floor on a float error.** Both stimtime and t0 lie on a 0.01 grid, so the division returns values such as `400.9999999999991` and `405.99999999999454` (as written in `laser_onsets.csv`). `floor` of these gives 400 and 405. This happens for **134 of 354 reaches (38%)**: 0% in 210515, 79% in 220516, and a different fraction in each session. Those pulse windows cover onset−1 … onset+4, so they include a pre-laser bin and drop the last bin.
  - The pseudo-onsets are drawn from the same floored values, so the control phase moves the same way on average. The floor+1 variant is "correct" for these 134 reaches and one bin late for the rest.
- **Failure scenario:** stimtime 942.20 and t0 938.19 give onset_float 400.99999… and a window of 400–405. The laser bin is 401.
- **Severity:** major. The window alignment differs from the preregistration by one bin in a session-dependent fraction of reaches, which also blurs the pulse response that d_pulse must absorb. The round and floor+1 variants (−0.19 and −0.19, both inconclusive) bracket the effect, so a change in the S1 conclusion is unlikely.
- **Fix:** re-extract with `%.17g` or `repr`, and use `np.floor(x + 1e-9)`.
- **Confidence:** high.

### 4. MAJOR: the validation is easier than the real setting (check 7)
- **Where:** `validate_stimfit.py:14`, `:21`, `:37`, `:41`, plus the absence of a shuffle null.
- **What's wrong:**
  - **Fit range.** Validation uses 300–560 (`:14`); the real data used 0–700 (issue 1).
  - **Onsets.** Validation draws onsets from {400, 401} (`:37`), so the pseudo-onset pool has two adjacent values and the control phase match is trivial. Real onsets span 375–418, with session spreads up to 20 bins.
  - **Exact onsets.** Validation onsets are exact integers, so floor equals the true bin. Real onsets carry issue 3.
  - **Field structure.** Validation fields are identical across blocks and reaches (`:21`). There is no trial-to-trial common gain, no block drift and no post-reach structure, which are the features that make κ_control ≠ 0 in real data.
  - **Smaller setting.** Validation uses N = 12 (the real data go up to 16) and the same number of reaches in every block.
  - **No null.** The shuffle null and the null correction are never simulated.
- **Consequence:** the validation's claims (κ_control ≈ 0, rate-only bias +0.08, single-session SD 0.12–0.15) do not carry over. Real κ_control reaches ±1, and RESULTS Caveat 3 already notes that real noise is larger.
- **Severity:** major, as an interpretation issue.
- **Confidence:** high.

### 5. MINOR: in the round and shift1 sensitivity variants, the control pseudo-onsets are not shifted
- **Where:** `run_stimfit.py:55-56` vs `:65`.
- **What's wrong:** the pulse uses `rint` or `floor + 1`, but the control always samples `floor(of)`. In shift1, the control window is one bin earlier in phase than the pulse window, which adds a phase confound to that variant only.
- **Severity:** minor. It affects a sensitivity row; the PREREG text does not say which choice was intended.
- **Confidence:** high.

### 6. MINOR: κ is unbounded below −1
- **Where:** `stimfit_model.py` (κ unconstrained in L-BFGS-B).
- **What's wrong:** κ < −1 flips the sign of J_eff. 210514 has a primary κ_pulse of −1.22 (median over subsets), and 210421 has −0.85. "Coupling scale" is not a meaningful reading in this regime. These values most likely reflect misfit (issue 1) rather than a reversal of coupling.
- **Severity:** minor, an interpretation issue.
- **Confidence:** high on the fact.

### 7. UNVERIFIED: the time origin of t_k
- **Where:** `merge_laser_onsets.py:22`, and `09_.../export_spikes_v2.py:16` (t = column 0 of the bin10 matrix, rows 100:800).
- **What's unknown:** whether column 0 is the bin start, centre or end, and whether row index 400 of the exported array is the 1-cm crossing (source row 500). Neither can be checked from the code. If t is the bin end or centre, every onset is shifted by 1 or 0.5 bin. The median onset of exactly 400.0 is consistent with t being the bin start and with the trigger at the crossing, but this is not proof.
- **Action:** confirm against the MATLAB binning code.
- **Confidence:** low that a problem exists.

## Checks that passed
- **Likelihood and gradient (check 3):** the per-unit logZ uses a = 1 + κ_g only for units in group g, and 1 elsewhere. The intercept d_g is added only to window units. Units pool bins by (block, t, group), which is valid because fields depend only on (b, t, g). The gradients for W, D, κ and J match finite differences (3e-8), and the likelihood matches brute force (2e-13).
- **Window construction (check 3):** `pulse[r, on:on+6]` gives onset…+5, as preregistered. Fixed control `401:407` gives 401–406, as preregistered. Clipping at 700 is never triggered. All windows (375–423) lie inside the 5-bin knot region (340–555) for both bases, so edges do not distort them; the edge problem lies at 555–699 (issue 1).
- **Pseudo-onsets (check 2):** they are drawn from the same session's stim_1 `floor(onset)` over the kept stim_1 reaches, one per stim_0 reach. The seed `[SEED0, date, 7]` is re-created in every task, so the draw is identical for the primary fit, all 20 shuffles and the S3 control (verified). The stim_0 reach set is identical for real and null fits: the shuffle permutes within rows after the design is built.
- **Subsets (check 4):** `default_rng([SEED0, date])` gives 10 subsets that are deterministic and identical for real, null and variant fits (verified). Shuffle seeds include the subset index.
- **Excludes and drops (check 5):** the primary analysis keeps `exclude == 0` in all three blocks. All 354 non-excluded stim_1 reaches have a finite onset, and all 400 stim_1 reaches do when excluded ones are counted, so no reach is dropped silently. Pulse rows stay aligned with `Xk[1]` rows (sorted nonzero indices). All 3354 fits converged, so the convergence filters in `analyze_stimfit.py` drop nothing.
- **S2 (check 6):** `thermo_small.window_thermo` computes I and χ_J at κ = 0 with fields B·W_b + d_g for exactly the pulse units (stim_1) and control units (stim_0), weighted by bin count. Multi-information = S_indep(model marginals) − S_Ising, in bits, divided by N. This is correct as specified. It inherits issue 1 (model and bin range).
- **S3:** the early/late split follows row order (chronological, since reachnum is sorted), and washout pseudo-onsets come from the same pool.
- **merge:** the reach mapping (reachnum − 1 → ReachS row) is asserted against the stim code. The MATLAB `[0 0]` empty placeholder is handled.
